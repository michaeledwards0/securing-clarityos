# Phase 2 — Fix

Every fix is in Terraform or application code, merged by pull request and applied by CI. No portal-only changes.

## Agent least privilege (F2, F3)

Terraform: [`terraform/agent-access.tf`](../terraform/agent-access.tf)

Each agent identity gets **Key Vault Secrets User scoped to individual secrets**, generated from an explicit allowlist:

| Agent | Secrets it can read | Before |
|---|---|---|
| Dashboard | 20 | whole vault |
| Voice | 7 | whole vault (including `stripe-secret-key`) |
| n8n | 0 | whole vault |

The allowlists came from searching every `getSecret` call in the dashboard and voice-relay code. A new secret an app needs has to be added to the list, so every access change shows up as a reviewable line in a PR diff.

I rolled it out in two applies so no app lost access mid-deploy: per-secret grants first, alongside the old vault-wide ones, then the vault-wide grants removed.

For the database, n8n moved from the RLS-bypassing owner login to its own `clarity_n8n` login, including the Postgres credential its workflows use **[VERIFY: n8n's "Clarity Postgres" workflow credential is `clarity_n8n`, not the admin login]**. The dashboard and voice-relay connect as `clarity_app`, a role with `nobypassrls` that owns nothing ([`src/0008_app_role.sql`](../src/0008_app_role.sql)), so tenant isolation policies actually apply.

## Authentication between agents (F4, F6)

Terraform: [`terraform/agent-access.tf`](../terraform/agent-access.tf) (top section)

One shared secret per direction, generated by Terraform and stored in Key Vault, so each caller holds only the secret for the hop it makes:

| Secret | Held by | Protects |
|---|---|---|
| `n8n-webhook-secret` | dashboard, voice-relay | n8n webhooks (`kb-ask`, `kb-embed-document`, `summarize-inquiry`) |
| `booking-turn-secret` | n8n | voice-relay `POST /booking/turn` |

n8n and voice-relay check the header on every request. Verified: an unauthenticated call to `kb-ask` now returns **403**.

In the same change, `kb-ask` builds its response with `JSON.stringify` instead of string concatenation (F6).

## Supply chain (F5)

n8n is pinned to `docker.io/n8nio/n8n:2.41.7`, the version that was actually running. Upgrades are now a PR that bumps the tag, so schema migrations happen when I choose them.

## Keyless AI services

Both AI resources have `local_auth_enabled = false`, so **no API keys exist**. The only way in is an Entra token.

| Resource | Caller | Role (scoped to the one resource) |
|---|---|---|
| Content Safety ([module](../terraform/modules/content-safety/main.tf)) | voice-relay identity | Cognitive Services User |
| Foundry / Azure OpenAI ([module](../terraform/modules/ai-foundry/main.tf)) | API Management identity | Cognitive Services OpenAI User (inference only, no key or deployment access) |

## Azure OpenAI model on Foundry

- Model: `gpt-4.1-mini` (`2025-04-14`), GlobalStandard, 50K tokens per minute **[VERIFY: model, version and capacity as deployed]**
- Content filter `Microsoft.DefaultV2` (harm categories plus jailbreak detection at the model layer), `NoAutoUpgrade` so model version changes are deliberate
- voice-relay's booking-intent classification runs on it **[VERIFY: `detectBookingIntent` routed through the gateway in production]**, so live caller traffic is in scope for **Defender for AI services**

**Why Azure OpenAI and not Claude on Foundry:** Defender for AI services documents coverage for Azure OpenAI and Azure AI Model Inference deployments, not Anthropic models on Foundry. The model that carries caller traffic had to be one Defender can inspect. Claude still handles the rest of the conversation through Anthropic's API.

## AI gateway: Azure API Management (F7)

Policy: [`apim/ai-gateway-policy.xml`](../apim/ai-gateway-policy.xml)

API Management sits between the agents and Azure OpenAI:

```
voice-relay --(Entra token, its managed identity)--> API Management --(APIM managed identity)--> Azure OpenAI
```

| Control | How |
|---|---|
| Caller authentication | `validate-azure-ad-token`: only listed agent identities get through |
| Backend authentication | `authentication-managed-identity`; no keys anywhere in the path |
| Per-agent token limits | `llm-token-limit` keyed on the calling identity **[VERIFY: tokens-per-minute value]** |
| Token metrics per agent | `llm-emit-token-metric` with the caller as a dimension, into Application Insights |
| No bypass | voice-relay's direct role on the Foundry account removed, so the gateway is the only path **[VERIFY]** |
